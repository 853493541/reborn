## Fix plan (implement the client's own calls in the viewer)

- **item-creation**: materialize `AppendItemFromIni`/`AppendContentFromIni`
  (clone the named INI subtree under the container), `CreateItemData`/
  `AppendItemFromData` (rows from the real table data), `Clear`/`RemoveItem`
  (drop existing clones). This is what fills every list (bag rows, friend rows,
  mail list, skill rows, activity rows).
- **arrangement**: after materializing items, run the engine's passes in recorded
  order — `FormatAllItemPos`/`FormatAllContentPos` (grid/flow placement),
  `SetSizeByAllItemSize`, `CorrectPos`, `SetPoint` (anchor placement),
  `SetScrollPos`/`SetStepCount`/`EnableScroll` (scroll offset/range),
  `SetOverTextPosition`/`SetOverTextFontScheme`.
- **render**: `FromUITex`/`FromIconID`/`FromTextureFile` switch the image source at
  runtime (missing-art counts change with the real source), `SetImageType` the
  render mode, the Animate* calls the frame animation.
- **state**: `Enable`/`Check`/`Expand`/`ActivePage` mirror the control state into
  the render (disabled look, checked frame, expanded groups, active page).
- The recorded calls are the client's own; the fix is execution, not approximation.
