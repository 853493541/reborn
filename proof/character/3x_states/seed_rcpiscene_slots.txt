Lazy "RCPI_Scene" name-hash seed — water-entry AV root cause (2026-10-06)
=========================================================================

Crash signature
---------------
- Fault: KG3DEngineDX11EX64.dll+0x12282B3, AV 0xc0000005, `mov rbx,[rdi]` with rdi=0
  (WER dumps: reborn_client_3x.exe 21:44:34 pid 0x65D8; reborn_client_3x_states.exe
  22:17:12 pid 0x9214; earlier 21:57:00).
- Trigger: the actor below a map water surface (龙门寻宝 NE lake basin) — walking in,
  standing at the bed, or spawning in the basin.
- Site disasm (0x1812282A6): `call 0x18105cf50` (hash-keyed rbtree find) returns NULL;
  the caller's `je 0x1812282b3` jumps INTO the deref (rdi stays 0) -> AV.

Root cause
----------
The lookup key is the engine's lazily computed FNV-1 of "RCPI_Scene":
- magic static { guard dword @RVA 0x2D5BD08, value qword @RVA 0x2D5BD10 } (this site);
- init lambda hashes the string at VA 0x1821CB2A8 = "RCPI_Scene" (FNV-1: mul 0x100000001b3,
  xor byte; basis 0xcbf29ce484222325);
- the guard gate (`cmp [guard], tls; jg init`) can let a render worker thread read the
  value before init -> value 0 -> lookup miss -> NULL deref. Same class as D6, which
  seeded only its own slot (RVA 0x2D5BBD0).
- FNV-1("RCPI_Scene") = 0x392E0BFA0428F080 (validated: equals the D6 seed constant).

Fix
---
client/RebornClient.cs seeds the 129 value slots with 0x392E0BFA0428F080 before LoadMap
(only when the slot is 0), gated on the engine PE timestamp 0x6AA7C1F5 (slot RVAs are
build-specific). RC_SEED_RCPISCENE=0 opts out (A/B). Log line: `lazyseed: rcpiscene
base=0x... slots=129 seeded=121`.
