## CLASSICAL (normal) — `op=classical`

```
movetest strafe mode=classical yaw0=2.38 yaw1=2.38 d=0.00 cam0=2.34 cam1=2.34
movetest back   mode=classical yaw0=2.38 yaw1=2.38 d=0.00 cam0=2.34 cam1=2.34
movetest turn   yaw0=2.38 yaw1=4.26 d=1.88 cam0=2.34 cam1=0.71 camd=-1.62
land drop=600u roll=1 clip=f1b02yd握拳小跳c.ani rc=0
```
clip switches: `F1b02yd挪步左.tani` (strafe window), `F1b02yd后退01.tani` (back window).

- Strafe/back input moves the character with the **facing kept** (d=0.00) and
  selects the authored **side-step / back-pedal** clips — the classical game
  truth (`OPERATION_MODES_PLAN.md` §1).
- Turn keys: character +1.88 rad; camera yaw 2.34 -> 0.71 — the
  `cameraYawBehind` reflection (behind(4.26) = 4.712-4.26 = 0.45) with the
  15 deg `CameraAdjustYawWhenMoveTurnDisableAngle` drag lag (~0.26), so the
  camera stays behind through the turn.
- Landing roll branch unchanged.

## JOYSTICK — `op=joystick`

```
movetest strafe mode=joystick yaw0=2.38 yaw1=0.81 d=-1.57 cam0=2.34 cam1=2.34
movetest back   mode=joystick yaw0=0.81 yaw1=-0.77 d=-1.57 cam0=2.34 cam1=2.34

land drop=600u roll=1 clip=f1b02yd握拳小跳c.ani rc=0
```

- Strafe/back input **turns the body to the travel heading** (d = -1.57 rad per
  1 s window at the pi rad/s turn rate) — the joystick game truth; no strafe /
  back-pedal clips are selected.
- Movement does not move the camera (mouse owns it in joystick mode).
- Turn keys behave as in classical (camera drag), independent of this run's
  mouse-driven camera.

## Correction 2026-10-01 — classical A/D turns (bytecode re-decode)

Re-decoded the real handlers from the packed bytecode (`tools/controls/lua51_probe.py`):
StrafeLeftStart = proto 0/76, StrafeRightStart = 0/78; forward/back/turn = 0/65-0/74.
STRAFE is the only mode-branched movement command: CLASSICAL -> SetControl +
TurnLeft/RightStart when Camera_IsInFreeView(); JOYSTICK -> ResponseWASDKey
(double-tap aware). The earlier summary in OPERATION_MODES_PLAN.md (classical
strafe keeps facing) described only the non-free-view branch — corrected.

Host mapping: RC_FREEVIEW=1 (default) = A/D turn in classical (observed game
behaviour); RC_FREEVIEW=0 = decoded side-step branch.

Runs (RC_DEMO_MOVE=1 RC_AUTORUN=15000, exit 0):

| run | strafe line | back line |
|---|---|---|
| classical, default (free view) | `movetest strafe mode=classical yaw0=2.38 yaw1=-0.76 d=-3.14 cam0=2.34 cam1=5.22` | `d=0.00` + 后退01 (back-pedal) |
| classical, RC_FREEVIEW=0 | `movetest strafe mode=classical yaw0=2.38 yaw1=2.38 d=0.00` (side-step; 挪步 clips) | `d=0.00` |
| joystick | `movetest strafe mode=joystick yaw0=2.38 yaw1=0.81 d=-1.57 cam0=2.34 cam1=2.34` | `d=-1.57` |

d=-3.14 = 1 s hold at the host turn rate pi rad/s; classical camera follows
(cam 2.34 -> 5.22, cameraYawBehind reflection + 15 deg drag). Landing roll
unchanged (`land drop=600u roll=1 ... rc=0`).

## Full classic movement matrix (2026-10-01)

Decoded the 8-way intent system: ResponseWASDKey (hotkeys.lua proto 0/46)
merges Forward/Backward and (TurnLeft|StrafeLeft)/(TurnRight|StrafeRight)
into MOVE_FORWARD / MOVE_LEFTFORWARD / MOVE_BACKWARD / ... and passes them to
ResponseDisplacementHotkey (proto 0/44, the sprint/轻功 skill dispatcher).
Host classic matrix: A/D alone turn (camera follows); W+A / W+D run the
camera-relative 45 deg diagonal with the character facing it (camera
untouched); S / S+A / S+D back-pedal at walk pace (number.krl ships no back
speed; walk 6 u/f = 96 u/s) with the facing kept; arrows always turn.

Run RC_DEMO_MOVE=1 RC_MODE=classical RC_AUTORUN=20000, exit 0
(log reborn_20261001_083417.log):

`

384 u over 1.2 s = 320 u/s run speed; 96 u/s = walk pace back-pedal.

## Classic free view resolved + W+A/W+D curves (2026-10-01, correction)

Decoded the free-view gate from the shipped scripts:
- Camera_IsInFreeView = mainscene.lua proto 0/1 (returns a state local).
- CameraStatus_Animation(isOn) (proto 0/0) swaps the Turn* globals to the
  Strafe* handlers when free view is OFF (and restores them when ON).
- CameraStatus_Set (proto 0/3) ends with CameraStatus_Animation(mode ~=
  'god camera'); CameraCommon.lua enters 'local camera' for the player ->
  FREE VIEW IS ON in normal play.
So the classical strafe handler (proto 0/76) free-view branch runs in normal
play: A/D call TurnLeft/RightStart -> A/D TURN. W+A / W+D therefore turn the
view while W runs: a curve. The earlier host diagonal interpretation was
wrong and is reverted. Host keyboard turn rotates the view at the char turn
rate (standing still the body turns with it; while moving the body follows the
rotating heading via the turn model), and curYaw/camSys.Yaw are wrapped each
frame (an unwrapped facing aliased dYaw across +/-pi and flipped turns).

Run RC_DEMO_MOVE=1 RC_MODE=classical RC_AUTORUN=20000, exit 0
(log reborn_20261001_085528.log):

`
movetest strafe mode=classical yaw0=-2.85 yaw1=0.29 d=3.14 cam0=1.28 cam1=-1.86   # A alone: turn (wrapped +/-pi)
movetest back   mode=classical dpos=(-27,-92) dist=96                              # S: 96 u/s walk-pace back-pedal
movetest turn   yaw0=0.29 yaw1=2.17 d=1.88 camd=4.40 (=-1.88 wrapped)              # arrow turn 1:1 view+body
movetest WA     dpos=(56,185) dist=194 dyaw=-3.75 dcam=-2.51 (=+3.77 wrapped)      # W+A: left curve (dist 194 vs 384 straight)
movetest WD     dpos=(53,186) dist=194 dyaw=3.71  dcam=2.52 (=-3.77 wrapped)       # W+D: mirrored right curve
`

Joystick sanity: strafe d=4.71 turn-to-heading cam unchanged; back dist=320
run; WA dist=348 no camera turn.

## Turn rate = local data; RMB owns the camera (2026-10-01)

1. Turn rate: the keyboard turn is a LOCAL action. The camera-controller row
   default table (.rdata 0x180d0 a table: 0.00314, 1.56, 6.28...) holds
   RotationSpeed = 0.00314 rad/ms = pi rad/s; the host now derives
   charTurnRate = RotationSpeed * 1000 (pi only as missing-row fallback).
   Verified unchanged: A-alone turn d=3.14 in 1 s (log 20261001_172009).

2. RMB hold: while RMB (CAMERAORSELECTORMOVESTICKY /
   CONTROL_OBJECT_STICK_CAMERA) is held, the mouse owns the camera - keyboard
   turn must NOT rotate the view. Verified (RC_DEMO_RMBWA=1, W+A held, RMB
   held, no mouse motion):
     movetest WA mode=classical rmb=1 dpos=(315,-221) dist=385 dyaw=0.00 dcam=0.00
   i.e. no camera turn, no body turn, straight run - exactly the observed game
   behaviour. With a simulated mouse drag (RC_DEMO_RMBWA=2) only the mouse
   rotates the camera: dcam=-1.08 (was -3.44 before the fix, which wrongly
   included the keyboard turn).

Also corrected while digging: the number.krl field offsets are walk +0x48,
run +0x4C, swim +0x50, **yaw turn +0x54**, yaw reset +0x58 (the movement
research doc lists them 4 bytes high).
