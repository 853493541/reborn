## 2. Five-ray and nine-ray sets

The helper starts at `0x1804c1b40` and receives the desired camera point in
`rdx`, anchor/look-at point in `r8`, and output point in `r9`. Its ray-query
scene is `[this + 0x118]`.

```asm
0x1804c1bb0: cmp      dword ptr [rcx + 0x15c], 0
0x1804c1c06: je       0x1804c1fba ; default five-ray branch
```

Base-camera constructor `0x180447770` zeroes `+0x15c` as part of the qword
store at `+0x158`, so the default is the five-ray branch. That branch builds
one center pair and four corner pairs from the two camera-basis offset vectors
and uses a five-iteration query loop:

```asm
0x1804c1fba: call     0x180633e30
... ; center endpoints and four +/- basis-corner endpoints are built
0x1804c22ba: mov      rbx, edi
0x1804c22bc: lea      r15d, [rdi + 5]
...
0x1804c2370: dec      r15
0x1804c2373: jne      0x1804c22c0
```

When `+0x15c != 0`, the helper builds a center pair first, then eight
perimeter pairs. `r14d` advances by 2; angle generation multiplies by pi and
1/8, producing 0, 45, …, 315 degrees. `r15d=9` then queries the center plus
those eight points:

```asm
0x1804c1cb8: mulss    xmm6, dword ptr [rip + ...] ; pi
0x1804c1cc0: mulss    xmm6, dword ptr [rip + ...] ; 0.125
0x1804c1cfd: add      r14d, 2
0x1804c1d0c: add      rbx, 0xc
...
0x1804c1e35: mov      r15d, 9
```

## 3. Ray direction and hit response

For each pair, the helper subtracts the anchor-side point from the camera-side
point, normalizes the direction from anchor toward camera, and calls scene
query wrapper `0x180475800` with the anchor-side point as origin. The maximum
distance is the segment length and the output begins at `FLT_MAX`:

```asm
0x1804c1e40: movss    xmm2, dword ptr [rsp + rbx + 0x60] ; camera-side x
0x1804c1e52: subss    xmm0, dword ptr [rbp + rbx - 0x2c]
0x1804c1e58: subss    xmm2, dword ptr [rbp + rbx - 0x30]
0x1804c1e8a: call     0x180633c66                     ; segment length
0x1804c1ea2: call     0x18055e650                     ; normalize direction
0x1804c1ebb: mov      rdx, r14                        ; anchor-side origin
0x1804c1ec3: mov      dword ptr [rsp + 0x30], 0x7f7fffff
0x1804c1ecb: call     0x180475800
```

Successful query distances are reduced to the nearest hit. The minimum output
distance is floored to 0.001 u. When a hit exists, the helper normalizes the
center line and writes `anchor + normalize(candidateCamera - anchor) * nearestHit`;
with no hit, it returns the candidate unchanged:

```asm
0x1804c1ef5: comiss   xmm12, xmm6                    ; xmm12 = 0.001
0x1804c1eff: test     edi, edi                       ; any probe hit?
...
0x1804c1f46: call     0x18055e650                    ; normalize center line
0x1804c1f7b: mulss    xmm0, xmm6                     ; direction * nearest hit
0x1804c1f7f: addss    xmm0, dword ptr [rbp - 0x30]   ; anchor origin + offset
...
0x1804c2446: mov      dword ptr [r12], eax           ; output x
0x1804c244e: mov      dword ptr [r12 + 4], eax       ; output y
0x1804c2457: mov      dword ptr [r12 + 8], ecx       ; output z
```

## 4. Scene query option

`0x180475800` obtains the `KG3DEngineXRepresentLogic` singleton and dispatches
its slot-0 ray query. The camera helper supplies option `1`. That option maps
to filter mask `0x301` in `0x180446920`; the mask is passed to lower scene
query function `0x18032ea40`:

```asm
; 0x180475800
0x180475854: mov      dword ptr [rsp + 0x28], 1
0x18047585a: call     qword ptr [r10]

; 0x180446920, option bit 0 -> internal query mask
0x180446945: and      r10d, 1
0x180446949: mov      ecx, 0
0x18044694c: mov      edx, 0x301
0x180446954: cmovne   ecx, edx
...
0x180446a28: mov      dword ptr [rsp + 0x40], ecx
0x180446a5b: call     0x18032ea40
```

The lower dispatcher evaluates several query backends enabled by mask bits
8/9 and the additional query argument, then keeps the closest positive hit.
The symbolic meanings of those mask bits/backends are not recovered.

## 7. Camera filter selection, RTTI and methods

The query wrapper 0x180446920 picks the intersection filter from option bit 0.
Option 1 (the camera path) selects the static FilterCamera object; option 2
selects FilterLogic:

  0x180946678 -> vtable 0x1806dda58 -> COL 0x18073f8b8
      '?AUFilterCamera@?A0x573b9fc1@@'
  0x180946688 -> vtable 0x1806dda88 -> COL 0x18073f9b8
      '?AUFilterLogic@?A0x573b9fc1@@'

  0x1804469fc: test r10d, r10d            ; option & 1
  0x1804469ff: je   0x180446a0a
  0x180446a01: lea  rax, [0x180946678]    ; FilterCamera
  0x180446a08: jmp  0x180446a18
  0x180446a0a: lea  rax, [0x180946688]    ; FilterLogic
  0x180446a11: test r9d, r9d              ; option & 2
  0x180446a14: cmove rax, r8              ; (r8 = 0)
  0x180446a28: mov  [rsp+0x40], ecx       ; mask (0x301 for option 1)
  0x180446a2c: mov  [rsp+0x38], rax       ; filter object
  0x180446a5b: call 0x18032ea40

Filter slot 0 (identical in both filters) calls 0x180254080 and tests +4,
i.e. the KG3DMesh bObscatleCamera bool:

  0x180446560: sub  rsp, 0x28
  0x180446564: mov  rcx, rdx
  0x180446567: call 0x180254080
  0x18044656c: xor  edx, edx
  0x18044656e: mov  ecx, 0x80004005
  0x180446573: cmp  dword ptr [rax+4], edx
  0x180446576: cmovne ecx, edx            ; S_OK when bObscatleCamera != 0

FilterCamera slot 1 (0x1804465c0) returns E_FAIL unconditionally; slot 2
(0x180446580) calls [obj vt+0xad8] and [obj vt+0x38] and special-cases type
0x3f. FilterLogic slots 1/2 (0x180446600, 0x1804465f0) return S_OK
unconditionally. The COM-style contract (which return value means "skip") has
not been confirmed from the visitor call sites.

## 12. Engine track-camera field usage

FOV block get/set (camera vtable +0x60 / +0x68):

  0x180448410: copies [rcx+0x48..+0x54] to four out-pointers
  0x180448d10: stores xmm1..xmm3 + stack float to [rbx+0x48..+0x54] and fires
               a settings-change event (GetTickCount + event helper)
  The [Camera] loader seeds the block from the live camera via vt+0x60 and
  applies fFovy plus three more floats via vt+0x68 (0x1804c1a69..0x1804c1ae1).

Key-rotation path (0x1804c3090..0x1804c31c2):

  0x1804c30cc: cmp dword ptr [rbx+0x2b0], 2       ; nChaseType
  0x1804c30e7: cmp dword ptr [rbx+0x2b0], edi     ; vs 0
  0x1804c317f: movss xmm1, dword ptr [rbx+0x2b4]  ; fChaseRate
  0x1804c3191: mulss xmm1, xmm0                   ; * direction (-1/0/+1)
  0x1804c3195: mulss xmm1, xmm9                   ; * dt
  0x1804c319a: addss xmm1, dword ptr [rbx+0x26c]  ; angle accumulator
  0x1804c31b8: mov dword ptr [rbx+0x26c], 0       ; reset when wrapped
  0x1804c312f..0x1804c3165: wrap by the 2-pi const 0x180671380
  => nChaseType selects the camera-key mode; fChaseRate is the key-rotation
     rate (default pi rad/s).
