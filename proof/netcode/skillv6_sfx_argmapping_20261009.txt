## KG3D_CreateSFXFromFile @0x180be4000 prologue
  rcx=r14 (owner, REQUIRED non-null: test r14,r14 / je fail), rdx=rsi (path, REQUIRED),
  r8=r13 (a3), r9=[rsp+0x48] (a4), a5=[rbp+0x630], a6=rdi=[rbp+0x638], a7=[rbp+0x640] (dword),
  a8=[rbp+0x648]. It copies the path (0x104) then dereferences the later args.

## vs native/sfx_shim.cpp RC_Shim_SfxPlay
The shim calls `create(owner, path, NULL, &outParam, NULL, mtx, 0, owner)`:
  a1 owner OK, a2 path OK, a3=NULL (engine: tag object), a4=&outParam (engine: a string),
  a5=0 OK, a6=mtx OK-ish, a7=0 (engine: flag), a8=owner (engine: the OUT slot).
So a3/a4/a7/a8 are all wrong: notably a8 must be the out pointer (not owner), a3 is a tag-context
object and a4 a secondary path — both supplied by the engine's animation-tag context (`rdi`/`tagdata`)
which the host does NOT have (it plays a raw dummy model's tani via PlayAnimation, not a KG3D_SFXModel
tag). A direct factory call therefore cannot be made correct from the host.

## Conclusion / next probe (W4)
Do NOT keep guessing factory args. The real route is the engine's own **tag-spawn path**: spawn the
landing-zone `.Sfx` through the animation/SFX tag system (KG3D_AnimationTag / KG3D_SFXModel) so the
tag-context args exist, or find a scene-level "play standalone effect" API that builds them. The
`/loc`-style `__RTDynamicCast` play steps in the shim are only valid AFTER a correct create.
