## Engine region — the old "0xE2E842 memcpy caller" attribution is WRONG
`KG3DEngineDX11EX64.dll+0xE2E690` (fn) contains, right before +0xE2E842:
  0xE2E835  lea  rcx, [rip+0x1f106ac]   ; = KG3DEngineDX11EX64.dll+0x2D3EEE8  (matches the fault dst!)
  0xE2E83C  call [rip+0xde6116]         ; = GetCurrentThreadId
  0xE2E842  call [rip+0xde6108]         ; = **EnterCriticalSection**  (NOT memcpy)
  0xE2E86F  call [rip+0xde60eb]         ; = LeaveCriticalSection (paired)
So `engine+0x2D3EEE8` is a **CRITICAL_SECTION / lock global**, and +0xE2E842 is lock acquire — the
prior handoff's "memcpy caller at 0xE2E842" was a misread. The real fault is elsewhere (jemalloc).
The fn loops calling `0xE2DA70` over `ebx` entries (a per-frame vector update) under that lock.
